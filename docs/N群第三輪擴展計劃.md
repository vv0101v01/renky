# N 群第三輪擴展計劃

> 盤點基準：189 條 / 189 通過 / 11,890 實例 / 9.70 s；N 群 21 條、5.92 s。
> 702 個 `pub fn`，其中 48 個未被呼叫（依使用者指示保留）。

---

## 一、審視：本庫已裂成互不相通的兩半

這是本次盤點最重要的發現，三組數字就足以說明。

### 1.1 表達式樹只認得 4 個構造子

```
pub enum SpaceExpr {
  SLeaf(String, Mat[Q])          STensor(SpaceExpr, SpaceExpr)
  SSum(SpaceExpr, SpaceExpr)     SDual(SpaceExpr)
}
```

然而本庫**已經證明了律**的構造子有：⊗、⊕、*、Hom（N-06）、
Λᵏ 外冪（N-10）、同餘扭曲（N-08）、子空間（N-09）、實化（N-07）、
Kronecker 和 ⊞（N-24）—— 共 **9 個**。

樹只能表達其中 4 個（Hom 靠 N-06 化約為 ⊗∘* 擠進來，算 4.5 個）。
使用者最初要求的「把不同空間構造彼此組合」，目前只實現了一半。

### 1.2 catamorphism 只會合成兩種演算法

```
pub fn synth_inv     pub fn synth_det     pub fn synth_compare
```

就這樣。N-11 宣稱是「演算法合成器」，但它只能合成 `inv` 與 `det`。
trace、rank、adj、cube 有律卻不能被合成；
eig、chol、svd、pinv、expm、sqrtm 更是完全在外。

### 1.3 ℝ 軌的律全部不在搜尋引擎裡

| 演算法 | 有律？ | 在 `law_search` 的 Φ 集？ |
| --- | :-: | :-: |
| `jacobi_eigen` | ✔ N-21 ×303 | **✘** |
| `svd_jacobi` | ✔ N-22 ×134 | **✘** |
| `cholesky` | ✔ N-22 ×11 | **✘** |
| `pinv` | ✔ N-23 ×85 | **✘** |
| `expm` | ✔ N-24 ×54 | **✘** |
| `sqrtm_spd` | ✔ N-24 ×162 | **✘** |
| `ldlt` / `qr_householder` / `polar_decomposition` / `cond2` / `inertia` | 部分 | **✘** |

搜尋引擎的 Φ 集是 `{inv, trans, sq, adj, cube, det, trace, rank}` ——
**八個全是 ℚ 軌的線性／多項式運算**。

### 1.4 診斷

> **N 群實際上是兩個互不相通的系統：**
>
> **(甲) 生成器** —— N-01／02／11／12／13／26。只跑 ℚ 軌、只合成 inv 與 det、
> 樹只有 3 個算子。它能自動搜尋，但搜尋空間裡全是便宜的演算法。
>
> **(乙) 律庫** —— N-07／08／09／10／21／22／23／24／25。增益最大的全在這裡
> （×303、×162、×134、×814），但**每一條都是手寫的一次性義務**，
> 生成器讀不到、合成不了、也搜尋不到。
>
> 第二輪把 (乙) 做大了，卻沒有把它接回 (甲)。
> **第三輪的唯一主題就是把這兩半接起來。**

### 1.5 另一個必須處理的問題：N 群已成為執行時間瓶頸

| 群 | 條數 | 耗時 |
| --- | :-: | --- |
| A–J（基礎層 140 條） | 140 | 1.74 s |
| K/L/M（加速層 28 條） | 28 | 2.04 s |
| **N（結構律 21 條）** | **21** | **5.92 s（61%）** |

最慢的 10 條裡有 **7 條是 N 群**（N-13 977 ms、N-10 887 ms、N-26 862 ms、
N-06 689 ms、N-12 520 ms、N-14 519 ms、N-11 310 ms）。

第三輪若只是繼續加律，執行時間會失控。**必須同時處理效能。**

## 二、第三輪提案：統一

### ⭐ N-30 統一成本介面與軌道標籤

**問題**：`Cost` 現有 `wmul`（ℚ 軌）與 `flops`（ℝ 軌）兩個互不相通的計數器。
N-21 的 ×303 和 N-03 的 ×13 無法並列比較，因為量的是不同的東西。

**做法**：
- 為每條律加上 `track` 標籤（精確 ℚ／ℝ flop），增益只在同軌內比較
- 提供 `LawVerdict::cost(self) -> Int64` 依軌道取對應計數器
- 明文記錄「跨軌增益不可比」這條規則，並在報告中分軌排序

**價值**：這是 N-31／N-33 的前置件 —— 多態合成器必須能處理兩軌。
**風險**：低。**預估**：50 行。

---

### ⭐⭐⭐ N-31 多態 catamorphism —— 真正的演算法合成器

**這是第三輪的核心，也是整個 N 群一直宣稱但尚未做到的事。**

現況 `synth_inv` 把「要合成哪個演算法」寫死在函式名裡。改為：

```
pub struct PhiSpec {
  pname    : String
  pleaf    : (Mat[Q], Cost) -> PhiVal      // 葉上怎麼算
  pkron    : (PhiVal, PhiVal, Cost) -> PhiVal   // ⊗ 節點怎麼合成
  psum     : (PhiVal, PhiVal, Cost) -> PhiVal   // ⊕ 節點
  pdual    : (SpaceExpr, Cost) -> PhiVal        // * 節點
  pdirect  : (Mat[Q], Cost) -> PhiVal           // 直接法（基準）
}
pub fn synth(spec : PhiSpec, e : SpaceExpr, c : Cost) -> PhiVal
```

於是：
- `synth_inv` = `synth(phi_inv, …)`，`synth_det` = `synth(phi_det, …)`
- 新增 Φ 只要填一張 `PhiSpec`，**不必再寫一個遞迴函式**
- **`PhiSpec` 可以由 N-13 的定律表自動產出** —— 搜尋引擎找到
  `(Φ, C, ⊙)` 三元組後，`⊙` 就是該節點的合成規則

> 最後這點才是關鍵：**搜尋引擎的輸出直接變成合成器的輸入**。
> 現在這條管線是斷的 —— N-13 找到律、印在報告裡、然後人再去手寫 N-21。

**驗收**：至少 6 個 Φ（inv、det、trace、rank、adj、cube）走同一套 `synth`，
結果與現有 `synth_inv`／`synth_det` 逐例相同；
並示範**由定律表自動建構**一個 `PhiSpec` 並成功合成。

**風險**：中（`PhiVal` 需要是矩陣與純量的和型別）。**預估**：200 行。

### ⭐⭐ N-32 SpaceExpr 擴編 —— 補上缺的 5 個構造子

```
SExt(SpaceExpr, Int)        // Λᵏ，Gram = 複合矩陣（N-10 命題 180-1 已證）
SReal(SpaceExpr)            // 實化（N-07 定理 187-2 已證保正定）
STwist(SpaceExpr, Mat[Q])   // 同餘 AᵀGA（N-08）
SSub(SpaceExpr, Mat[Q])     // 子空間 SᵀGS（N-09）
SKSum(SpaceExpr, SpaceExpr) // Kronecker 和 ⊞（N-24）
```

構造子由 4 個增為 9 個。深度 3 的隨機樹，型態數由 ~40 增至 ~700 ——
**這才是使用者當初說的「組合爆炸」**。

**風險**：中（`sdim`／`sgram`／`sdepth` 等全部要擴，`SReal` 跨 ℚ/ℝ 軌需小心）。
**預估**：250 行。**注意**：`SExt` 會讓 N-12 分派器**首次真的選「攤平」**
（k 接近 n/2 時 C(n,k) 爆炸，分解反而不划算）——
這會驗證 N-12 一直沒機會驗證的那一半功能。

---

### ⭐⭐ N-33 ℝ 軌進入搜尋引擎

把 `{eig, chol, svd, pinv, expm, sqrtm, cond}` 七個 Φ 加進 `law_search`，
C 加上 ⊞，⊙ 加上「譜逐對乘積」與「譜不交併」兩個新規則。

候選數由 72 增至約 **250**。預期會自動重新發現 N-21…N-24 手寫的那些律
—— **這本身就是對生成器的最強驗收**：
它應該能自己找到人類已經手寫出來的東西。

**風險**：中。**效能**：必須配合 N-35 分層，否則執行時間爆炸。

---

### ⭐ N-34 裁決器型別擴充 —— 讓引擎看得見另外兩類律

N-26 已指認：引擎只能發現加速律，看不見不變量律（N-08 慣性）
與可行性律（N-07 實化），因為 `LawVerdict` 只有 `(holds, 成本比)`。

```
pub enum Payoff {
  Speedup(Double)      // 加速律：成本比
  Invariant(String)    // 不變量律：什麼被保持
  Feasibility(String)  // 可行性律：把問題搬到哪條可解的軌道
}
```

並為不變量律寫一個專用裁決器：
`check_invariant(名稱, 不變量函式, 變換, 試驗)` —— 驗的是
「變換前後該量相等」而非「兩條路徑結果相同」。

**價值**：N-26 的推論 188-3 說引擎有兩類盲區，本條消掉其中一類。
**風險**：低。**預估**：120 行。

---

### ⭐⭐ N-35 搜尋分層與 N 群效能整頓

**非做不可** —— N 群已佔 61% 執行時間，而 N-33 還要把候選數乘 3.5 倍。

1. **分層**：常規義務只跑精簡候選集（小網格、固定種子）；
   全量搜尋移入 `cmd/lawsearch/`，結果落檔 `docs/定律表.tsv`
2. **快取**：N-13／N-26 目前各自重跑一次完整搜尋（977 + 862 ms），
   應共用一次結果
3. **網格下修**：N-10 的 (6,3)、N-06 的 dim 20 是主要成本來源，
   下修並把大尺寸移入一次性實測

**目標**：N 群由 5.92 s 降至 **≤ 2.5 s**，即使加入 N-31…N-34 亦然。
**風險**：低，但工作量不小。

---

### ✅ N-36 取樣分布修復

N-26 發現 `rank/⊞/·` 的偽陽性源於測試矩陣全是正定 Gram。
現行 `rand_gram` 只產生 SPD 矩陣 —— **整個搜尋引擎都跑在這個偏差上**。

補上：不定號對稱、奇異、長方、整數病態（Hilbert 矩陣）四種分布，
並讓 `check_law` 在多個分布上各試一輪。
驗收：`rank/⊞/·` 必須從「成立」翻轉為「推翻」。

**風險**：低。**但影響面大** —— 可能翻掉現有定律表裡的若干條，
那正是它的價值。

## 三、第三輪動工順序

| 序 | 條目 | 理由 | 預估 |
| :-: | --- | --- | :-: |
| 1 | **N-35 效能整頓** | 先清地基，否則後面每加一條都更慢 | 中 |
| 2 | **N-30 統一成本介面** | N-31／33 之前置件 | 小 |
| 3 | **N-31 多態 catamorphism** | 第三輪核心：接通生成器與律庫 | 大 |
| 4 | **N-32 SpaceExpr 擴編** | 構造子 4 → 9，真正的組合爆炸 | 大 |
| 5 | **N-33 ℝ 軌進搜尋引擎** | 驗收：引擎應自己找到 N-21…24 | 中 |
| 6 | **N-34 裁決器型別擴充** | 消掉 N-26 指認的一類盲區 | 小 |
| 7 | **N-36 分布修復** | 可能翻掉既有定律，宜最後做 | 小 |

**第三輪結束時應能說**：
> 搜尋引擎找到一條律 → 定律表自動產出 `PhiSpec` → 合成器對任意
> 9 構造子表達式樹合成該演算法 → 成本代數預測增益 → 實測驗證。
> **全程無人介入。**

這是目前**完全做不到**的事（現在第 1 步到第 2 步之間斷開，要人手寫）。
