## 為何「零依賴」

`moon.mod` 之依賴區為空，函式庫本體（root `moon.pkg`）之 import 區亦為空，
連 `@math` 都未使用。（例外僅限兩支**執行檔**，皆為編譯器自帶之標準庫而非第三方套件：
`cmd/accel` 為了量掛鐘時間 import `moonbitlang/core/bench`；
`cmd/main` 為了讀取 `--only` 之子集前綴 import `moonbitlang/core/env`。
函式庫本體與全部 242 條義務自證皆不依賴兩者。）

| 需求 | 自建實作 |
| --- | --- |
| `sqrt` | Newton 迭代（`kernel.mbt`），附殘差憑證 |
| `sin` / `cos` | 區間歸約 + Taylor 級數 |
| `atan2` | 級數 + 象限修正 |
| `exp` | 縮放–平方 + Taylor |
| 有理數 ℚ | BigInt 既約分數（`rational.mbt`） |
| 複數 ℚ(i)／ℂ | 泛型 `Cpx[F]`（`complex.mbt`） |
| 四元數 ℍ | `Quat[F]`（`quatspace.mbt`） |
| 亂數 | xorshift64\*（確定性、可重現） |

## 加速層（K／L／M 群）

把 A–J 之精確演算法重寫到「多模 𝔽p → CRT 提升 → 有理重建 → **事後憑證**」之管線上。
正確性不靠機率論證：B 管（多模）負責*猜*，C 管（憑證）負責*證* —— 以精確算術驗證
`Ax = b`、`AX = I`、`TA = R`、`G | f ∧ G | g`、`f(xᵢ) = yᵢ`，憑證通過即無條件正確。

| 項目 | 基準 | 加速 | 增益 |
| --- | --- | --- | --- |
| ℤ 行列式 n=16（256 位元係數） | Bareiss 無分數消去 | 多模 CRT | **×4.4** |
| ℚ 線性方程組 n=14 | 高斯消去 | 多模＋重建＋憑證 | **×7.6** |
| ℚ 反矩陣 n=12 | 高斯–Jordan | 多模＋重建＋憑證 | **×8.7** |
| 特徵多項式 n=11 | ℚ Faddeev–LeVerrier | 多模 Hessenberg CRT | **×9.8** |
| 最小二乘 20×10 | ℚ 正規方程 | 𝔽p 組裝＋重建 | **×9.2** |
| ℚ[x] 乘法 deg 64 | ℚ 卷積（每步 gcd） | 清分母＋多模 NTT | **×5.3** |
| ℤ[x] gcd deg 16 | ℚ 歐幾里得 | 模 p 篩＋整除性憑證 | **×4084** |
| 【反例】由 32 根造多項式 | 線性累積 | 積樹 | ×0.60 ✘ |

增益以**確定性成本模型**計量（schoolbook 下 BigInt 乘法 = ⌈bits(a)/64⌉·⌈bits(b)/64⌉
次單字乘法），與平台無關、可重現、可審計；掛鐘時間另見 `moon run cmd/accel`。

最後一列是**誠實反例**：schoolbook 算術下積樹比線性累積更貴，分派器對此回答「不加速」。
**定理 Λ3-13（正向性）**：若判定函數 δ 滿足 `δ = true ⇒ cost_fast < cost_base`，
則「基準 ⊕ δ 分派」之成本逐點不劣於基準。目錄 **K-10／L-10／M-08** 在參數網格上
逐點實測此蘊含式，無一反例 —— 「正向優化」因此是被自證之性質，而非宣稱。

## 中端（第六輪）

把這個庫當編譯器來排：前端 `IPSpace[V,F]` → 中端 `SpaceExpr` IR → 後端特化演算法。

```
35 個載體各異的空間  --N-50 座標化重編-->  同一種表示（忠實 35/35，SPD 35/35）
  × 7 個構造子       --N-51 Gram 函子-->   245 個相異空間（維數 1–28）
  × D 群 23 條演算法 --N-52 全量普查-->    5,635 格，全數成立，0 推翻
                     --N-53 重寫規範化-->  10 條保 Gram 規則，物化成本 ×6.44
                     --N-54 按形狀派工-->  兩路逐元相同 48/48，整體 ×3.83
                     --N-55 ℝ 軌量誤差--> 最差誤差 9.14e-9 → 1.03e-14，無一式變差
```

三個雙向對照，缺一不可：

- **N-52**：5,635 格全過本身沒有說服力（恆真的判準式一樣漂亮）。故拿三個各
  破壞一條內積公理的 Gram 重跑，量出公理依賴圖 —— 退化型推翻的恰是 D-01／
  D-08／D-09，需要 Gram 可逆的那三條。
- **N-54**：有特化路徑的形狀要求成本嚴格下降；**沒有**特化路徑的（Λᵏ、⊞）
  要求兩路成本**一分不差** —— 它們走同一條程式路徑，差一分錢就是派工出錯。
- **N-55**：只報「誤差很小」分不出「規則正確」與「量測不靈敏」。故另跑一條
  故意寫錯的重寫，正確範式偏差 6.66e−16，錯誤重寫 9.11，相差 1.37e16 倍。

ℝ 軌那一條只有雙軌庫問得出來：同一個 `SpaceExpr` 在 ℚ 上算出**真值**，
兩條 ℝ 路線才有得比。只有浮點軌的庫拿到兩個近似值，互比只能知道「相差多少」，
不知道「誰靠近真值」。

詳見 [`docs/中端報表.md`](docs/中端報表.md) 與
[`docs/空間普查表.md`](docs/空間普查表.md)。

## 加速層重構（第七輪）

起點是兩條**誠實反例**：L-05（ℚ RREF 多模重建）與 L-08（Gram LDLᵀ 多模重建）。
翻開它們的義務會發現一件比「加速失敗」嚴重得多的事 —— 目錄寫著「實測 ×0.15」
「實測 ×0.6」，但義務只驗了正確性，**從來沒有量過那兩個比值**。
一條以負面結果為主張的條目，它的主張不在義務裡。

```
N-56  補上受計量的基準路徑 → 八格全輸，而且輸得有形狀
      L-05 比值隨位元下降 0.15 → 0.046；L-08 先升後降 0.15 → 0.81 → 0.65
      診斷：主成本是 Θ(ν·k²)，ν = 要重建幾個輸出
      一條保留下來的失敗嘗試：砍 k（先驗 Hadamard 界）反而更慢 ×0.75
N-57  L-08′ 只重建 n 個整數前導主子式    ν : n²+n → n    ×2.0 → ×107.6
N-58  L-05′ 秩與樞軸之模篩 + 夾擠憑證     ν : 2n²  → 1    ×1.28 → ×81.9
```

> **加速層的單位不該是「整個矩陣」，而該是「呼叫端真正要的那個量」。**

兩條改寫都不是「換個規模再量一次」，是把輸出換掉。正確性照樣無條件：
L-08′ 靠整數的 Hadamard 界（與 K-04 同一條定理，不需事後憑證），
L-05′ 靠兩條精確的夾擠憑證。**誠實邊界也寫進定理**：L-05′ 救得了
「秩滿不滿」（×81.9），救不了「秩虧多少」（×1.08 —— 上界憑證本身就幾乎是
一次完整的 ℚ 消去）。

詳見 [`docs/加速層重構.md`](docs/加速層重構.md)。

## 任意三表互乘（第七輪）

N-52 的普查寫死了三軸（D 群 × 空間 × 構造子）。第七輪把軸抽出來：
普查的輸入變成**任意三張表**，表項可以是空間、構造子、判準式，也可以是
目錄裡的一條義務。空間表擴為 45、構造子表擴為 14，兩者都**前綴保持**，
舊指紋繼續當迴歸錨點。

| 三表相乘 | step | 格數 | 通過 | 指紋 |
| --- | --- | --- | --- | --- |
| 空間₀ × 構造子₀ × D群 | 13 | 419 | 419 | `419:419:674552611` ← 必須重現 N-52 |
| 空間 × 構造子 × D群 | 17 | 774 | 774 | `774:774:352759555` |
| 空間⊥ × 構造子₀ × D群 | 1 | 966 | 867 | `966:867:761159647` |

引擎還量**逐軸敏感度**：固定另兩軸、沿某軸掃，格值會不會變。
一個 14,490 格的普查如果三軸全退化，實際上只是把同一個答案抄了 14,490 遍。
這裡有個陷阱 —— 在一個正確的函式庫上格值恆為真，敏感度必定量到 0，
**不是軸退化，是沒有訊號**。故備了擾動空間表（三個各破壞一條內積公理的
Gram），格值才會分裂：空間軸 23/36、構造子軸 2/36、演算法軸 14/36 有變動。
反向對照把第三軸換成字母群（那些條目根本不看空間），三軸必定全退化 0/0/0。

最後，義務生成器的 DSL 也跟著擴出第二種產出（N-62）：吃三表規格、
先跑一次普查、把量到的數字逐一釘進產出的 MoonBit 程式碼，
經 `cmd/genoblig` 寫入 `oblig_auto.mbt` 後編譯執行。三道防「寫小說」的檢查：
決定性、量測忠實、**敗例忠實**（餵一個必定有推翻的普查，產出必須如實寫
`pass < cells`，不能永遠寫全過）。

## 第八輪：五個補起來的洞

前幾輪在文件裡欠下的五筆，一次還清。

| | 欠了什麼 | 結果 |
| --- | --- | --- |
| N-63 | ⊞ 沒有 k 元成本模型，連計量都沒有 | f(p,q) = P·(p+q)，**看得見切法** ⇒ 要自己的 DP |
| N-64 | 類 B 交換律寫好了卻沒人用 | 帶上置換見證 ⇒ 逐元健全性取代 det+trace |
| N-65 | 子空間沒有特化路徑 | 「要的不是 G(A)，是 G(A)·S」⇒ ×1.353 |
| N-66 | N-40 的規則進不了求值管線 | 補算子層類 C 規則；**手寫的那條才是錯的** |
| N-67 | 範式的結合順序是約定不是最佳化 | 接 N-41 的區間 DP ⇒ A10 的代價歸零 |

幾個值得單獨說的發現：

**⊞ 不是 ⊗ 的變體。** A ⊞ B = A⊗I + I⊗B 逐項全是搬運，**沒有乘法**；
搬運次數 P·(p+q) 在 P 固定時仍隨切法而變，而 ⊗ 的 P² 不會。所以 ⊞ 的
區間 DP 轉移式裡多了一項依賴切點的成本。窮舉 k=4、維數 2…12 的 14,641 組：
兩個 DP 的最佳樹有 **6 組不同**，最大損失 ×1.02035（具名反例 `[5,2,2,9]`）。
結論兩邊都成立 —— ⊞ 確實需要自己的 DP，而 N-41 現成的是個誤差 2% 內的好近似。
另有一條可證的不等式：`cost⊞(T) ≤ cost⊗(T)` 對每一棵樹成立，
等號 ⟺ 每個內部節點都切成 2 與 2。

**自動合成的那一半是對的，手寫的那一半是錯的。** 把 N-40 接上中端的第一次，
40 組 (Φ, 式) 有 3 組對不上。出問題的不是機器量出來的 ⊗ 指數，是被當成
「對所有 Φ 都成立」寫死的 ⊕ 區塊對角規則 —— `adj(A⊕B) = det(B)·adj(A) ⊕ det(A)·adj(B)`。
修法不是再補一條手寫規則，是加一道**量出來的**守門。

**A10 的代價歸零。** 第六輪 N-53 的逐式側寫是 34 便宜／5 不變／1 變貴，
那一式是 A10 右結合正規序造成的（1,074 → 1,108），當時只記下來沒解決。
重新結合不需要置換（Kronecker 嚴格結合，Gram 逐元相同），所以「怎麼結合」
純粹是成本問題，而 N-41 早就解完了。接上去之後：1,108 回到 **1,074**。
整體效果只有 ×1.006 —— 隨機語料裡的 ⊗ 鏈大多只有兩個因子，DP 無事可做。

## 第十五輪：構造子加到 35 個，欠條清零

兩件事：使用者裁示**不再跑 45³**，以及 §25.6 的五筆全部做完。
另外把構造子從 14 個加到 **35 個**。

**砍掉 45³ ——「實例數不是覆蓋率」。** 第十四輪加的 45³ = 91,125 個
三元組維數層掃描，檢查的是 `dim P·(dim Q + dim R) = dim P·dim Q + dim P·dim R`
—— **整數乘法的分配律**，對任何三個正整數恆成立，不依賴 Gram、
不依賴空間、不依賴本庫任何一行程式。跑 91,125 次只是把同一條算術
恆等式抄 91,125 遍，而它佔了全庫實例數的 **47.5%**。一個指標如果
可以靠「把恆真的東西乘上組合數」拉高，那個指標就壞了。砍掉是修正。

**21 個新構造子**：張量族 ⊗W₃／T²／End／W₂⊗，直和族 ⊕W₂／3D／⊕*／⊞W₃，

**非退化那一項不是湊數的。** Λ³ 在 n = 2 時 C(2,3) = 0，而一個 0 維的
「內積空間」不會報錯 —— 它會讓正定判定（空的主子式序列恆真）、
Riesz（解 0×0 方程）、Cauchy–Schwarz（兩個空向量）全部落入未定義分支
而**靜默通過**。這比算錯難發現：錯的數字會被對照抓到，空的迴圈不會。

**ℚ 的共軛是恆等，所以 ℚ 版看起來「剛好對」。** 到了 ℂ 就算出不同的數
—— 不是慢一點或精度差一點。這類「在特例上恰好退化成正確」的程式最
危險，因為它在現有測試上全綠。對照因此設計成：不取共軛的版本在 ℚ 軌
恆等於正確答案（對照恆假、無內容），在 ℂ 軌必須算出不同的數。
**同一條對照在兩條軌上的強度不同，這件事本身要寫出來。**

**抽樣換成完整覆蓋。** LDL⊗ 原本只做隨機雙線性抽樣，因為「逐元驗證」
被預設成要先有那個 n_An_B 階矩陣。命題 K-6 說不必 ——
乘積側每一元都因式分解成兩個因子側的元，把因子側驗完（Θ(n³)）
就等於把 n_An_B 階的等式驗完。詳見設計文件 §二十六。

## 第十四輪：把上一輪的五筆欠條做完

設計文件 §24.5 列了五筆沒做掉的事。這一輪逐條清掉 —— 而清的過程裡
發現**那五筆看起來是五個缺口，其實是同一個**：第 1、2 筆的共同原因是
驗證路徑都要求先有一個 144 階的 ℚ 矩陣存在，不是那些命題在大配對上
不成立，是看它們的方法太貴。

| | 第十三輪 | 第十四輪 |
| --- | --- | --- |
| ⊗ IPSpace 層 | 1762（87.0%） | **2025（100%）** |

| `tensor_space` | 急性（算兩次 Gram） | 另備**惰性版** |

**保持結構，不要物化（定理 K-1）。** 以列優先把 x 視為 n_A × n_B 矩陣 X，
則 (A⊗B)x = A·X·Bᵀ —— 成本 Θ(n_An_B(n_A+n_B)) 對物化法的 Θ(n_A²n_B²)，
12⊗12 實測 ×6.00（理論 144/24）。有了它 `tensor_space_lazy` 就寫得出來，
Gram 從頭到尾不需要存在，IPSpace 層全表 **10.5 s → 2.1 s** 且覆蓋率
87% → 100%。這同時補上第 5 筆：`direct_sum` 從第一天起就是惰性的，
而 `tensor_space` 會呼叫兩次 `gram_of_space` 再物化 Kronecker 積，
兩個相鄰的建構子一急一惰而無人說明。

**行列式換軌，正定換證書。** 本庫忌諱物化 144 階矩陣是因為 ℚ 的元素
帶 gcd 與大數；在 F_p 上每元一個機器字、Θ(d³) 消去無係數膨脹，
所以「大配對的行列式無法獨立對帳」只在 ℚ 軌成立 —— 換軌，全表 0.2 秒。
正定那一半更有意思：原本的理由是「譜為 {λᵢμⱼ} 皆正」，那是一個
**可以相信的理由**而不是一個**可以檢查的物件**。改用**定理 K-2**：
A⊗B = (L_A⊗L_B)(D_A⊗D_B)(L_A⊗L_B)ᵀ，而 L_A⊗L_B 仍為單位下三角，
故右式就是 A⊗B 的 LDLᵀ 分解 —— 判準成本 Θ((n_An_B)³) → Θ(n_A³+n_B³)
（12⊗12 約 216 倍），而且手上多了一個可以拿去驗的分解。
兩條新路徑都不許自說自話：ℚ 軌的直接計算仍在 1495 對上跑並逐對帳。

**下毒的位置不能亂挑。** K-2 的對照第一版固定毒 D_A⊗D_B 的第 0 個元，
2025 對裡有 185 對抓不到 —— 因為該處 u[t]·v[t] = 0 時擾動在雙線性型上
不可見。**那是對照設計的錯，不是被測物的錯。** 改為先算出 u、v 再挑
一個乘積非零的位置後 2025/2025 全數失效。反過來，K-1 的對照
（把 Bᵀ 寫成 B）在註冊表 45 個全對稱的 Gram 上**結構性不可辨**，
所以照實記為不可辨、不宣稱抓到 —— 把一個不可能成功的對照寫成「通過」，
比沒有對照更糟。詳見設計文件 §二十五。

## 第十三輪：F-01 × 其他空間、F-02 × 其他空間

F-01（正交直和 P ⊕ Q）與 F-02（張量積 P ⊗ Q）的目錄欄位都寫
**「任意兩空間」**，而義務各跑**一對**具體空間。全稱命題，單點證據。
本輪與 45 個註冊空間全面相乘：45 × 45 = **2025 個有序配對**。

| | 內容 | 結果 |
| --- | --- | --- |
| **N-83** | ⊕ × 2025 對，七項判準 | 兩個驗證層級**都**跑滿 2025／2025 |
| **N-84** | ⊗ × 2025 對 | 全表判準 2025；det／正定 1495（73.8%）；IPSpace 層 1762（87.0%） |

**兩個驗證層級，證明力差很遠。** 在 Gram 層，「G(P⊗Q) = G_P ⊗ G_Q」
**是定義不是定理** —— 拿 `mkron` 當模型再去驗模型等於 `mkron`，
驗的是 `mkron` 自己。只有真的呼叫 `direct_sum`／`tensor_space` 造出

**超出者標記為未驗，不計入通過**。

**加速的單位還是那一條。** IPSpace 層一開始要 20 秒，剖開來看瓶頸
不在抽查而在建物件：`tensor_space` 對每個因子呼叫 `gram_of_space`
（Θ(d³)），在 45 × 45 的表裡同一個因子被重算 **45 次**。
改由呼叫端傳入因子 Gram 之後，覆蓋率從 73.8% 升到 87.0%
而時間反而下降。（順帶發現 `direct_sum` 是惰性的而 `tensor_space`
不是 —— 兩個相鄰建構子一急一惰，沒有任何註解說明為什麼。）
快路徑帶著一個不屬於張量積的前提：它假設註冊表的 `sg` 真的等於
`gram_of_space(space())`。那是關於註冊表的事實，住在兩個檔案之間、
不在任何一個裡面，所以它是獨立判準（45／45）而不是註解。

**分配律要見證，結合律不要。** 分塊對角與 Kronecker 在座標上嚴格
結合（逐元相等，連置換都不需要）；分配律則因兩側基底排列不同，
必須給出具體的指標映射。把三條寫在一起而不區分，會讓人以為一樣強。
兩側對照還多推一層：連「哪些三元組可比」都是算出來的
（維數相容 ⟺ d_P = d_Q，實測恰為 261），盲點同樣可預測
（⟺ G_P = G_Q，261／261 相符）。詳見設計文件 §二十四。

## 第十二輪：全部空間 × 七個構造子

45 個註冊空間（9 族，涵蓋題目所列全部 12 類）× 7 個構造子

這 315 格本來就在跑。問題是**它們驗到了什麼**：每格只檢查維數公式與
正定，所以一個算錯的 Gram 只要維數對、仍然正定，就能完整通過。
對稱平方尤其危險 —— 它的 Gram 由一個 n²×d 選擇矩陣夾出來，
寫錯交叉項的係數既不改維數也不破壞正定。

| --- | --- | --- |
| **N-78** | 七條封閉式（各與泛型 `sgram()` 無共用碼）＋ 盲點預測 | 封閉式一致 315/315；盲點預測=實測 315/315 |

**把兩側對照從「計數」改成「預測」。** 七條錯式都是真的會有人寫出來的錯
（忘記 Hom(W,−) 裡 W 是對偶地出現、忘記 Hodge 符號、張量指標寫反…）。
第一次跑完，一半的格抓不到 —— 而抓不到的那些不是隨機分佈的：
`**` 的 22 個盲點全部是 Gram 為單位陣的空間。於是對照改寫成
**先宣告哪裡會盲**（一條只看 G 的代數性質，如 `**` ⟺ G = I、

315/315 相符，其中 99 格為盲。理由是**只報計數的對照會隨註冊表成長

知道為什麼。

任何人都會說當然可交換 —— 量出來是維數 45/45 相同、Gram **0/45** 相同。
Kronecker 積不可交換，A⊗B 與 B⊗A 只差一個完美洗牌。
所以交換圖分三層（維數相同 ⊋ 置換等距 ⊋ 逐元相同），
見證是具名構造的 `Shuffle(2,2)⊗Iₙ`，44/44 通過；
沒有見證的 794 格誠實記為「未見證」而非「不同構」。

**封閉式的定義域比它取代的那條路徑小。** 接上 Λⁿ⁻¹ 之後，
45 個註冊空間全過、指紋一位元未變 —— 然後 N-61 與 N-73 紅了。
兩個 bug：封閉式由 adj(G) = det(G)·G⁻¹ 導出，要 G **可逆**
（`compound` 不要）；餘因子式給的是 adj(G)[j][i]，所以要取
G⁻¹[n−1−q][n−1−p]，我寫成了 [n−1−p][n−1−q]，**G 對稱時兩者相同**。
註冊表裡 45 個 Gram 全部對稱正定，對「這條式子依賴對稱嗎」
結構上無法提供任何訊息。抓到它們的是第六輪為了量軸敏感度而建的
擾動表 `空間⊥`。兩條前提現在都是 N-79 的判準，不是註解。
詳見設計文件 §二十三。

## 第十一輪：一個很像樣、而且是錯的診斷

第十輪結論是「要降時間得去動 N 群的掃描網格」。這一輪照做了，
結果不必動任何網格、也沒有少驗任何一格，全庫自證由 121.5 s 降到 **97.7 s**，
而且條目還多了三條。

**那個錯誤的診斷。** 單一最貴的葉節點是 `comb14_stats()` 的 9.4 秒，
它只做一件事 —— 對 630 個 Gram 判定正定。而 `is_positive_definite` 做
n 次**獨立**行列式（Θ(n⁴)），最大 Gram 78×78，約 9.3×10⁶ 次帶 gcd 的
ℚ 運算，數量級剛好對得上。更漂亮的是正確解法第七輪就寫好了
（L-08′「一趟消去給出全部前導主子式」），只是沒接上去。
故事完整、自洽、附一個很有說服力的反諷 —— 而且是錯的：

```text
  造出 630 個 Gram            8,427 ms      ← 真正的位置
  is_positive_definite ×630     1,073 ms
```

**真正的位置是十四分之一。** 逐構造子計時，`S²` 一個吃掉 97.5%
（7,941 ms），其餘十三個合計 202 ms。原因很笨：S² 的 Gram 走
`Sᵀ(G⊗G)S` 兩次稠密 ℚ 乘法，而 S 只是選擇矩陣，每行至多兩個 1 ——
拿它做稠密乘法等於付全價搬零。

| | 內容 | 結果 |
| --- | --- | --- |
| **N-75** | 對稱平方之封閉式 Gram（按形狀派工） | Θ(d·n⁴) → Θ(d²)，掛鐘 8,225 → 84 ms（**×97**），指紋一位元未變 |
| **N-76** | Sylvester 判準之 Θ(n³) 整數路徑（不換列 Bareiss） | 1,073 → 329 ms；錯誤診斷的殘骸，刻意留著 |
| **N-77** | 普查備忘錄與**繞過不變量** | N-60 10.63→0.77 s、N-62 22.64→10.16 s、N-73 12.85→9.68 s |

**N-77 是這一輪真正棘手的一條。** 同一個 774 格普查在庫裡被算了五遍
（約 17.5 秒），而它是純函數 —— 看起來就是「加個快取」。但 N-62 的兩條
主張是「生成器是決定性的」與「生成碼忠實」；備忘錄無差別接上去之後，
前者退化成「備忘錄回傳了同一個物件兩次」、後者退化成「同一個物件等於
它自己」。**兩條都還會通過，而且通過得更快** —— 測試還在、訊號沒了。
解法是把分工寫成一條可檢查的規則：

> **繞過不變量**：每一個被備忘的鍵，在義務集合中至少還有一處
> 繞過備忘錄、獨立重算、並與字面常數對帳的呼叫點。

另外，N-75 的第一版義務自己花掉 8.95 秒跑稠密參照 —— 一條目的在省時間的
義務花八秒說不過去。改用第三條獨立路徑（雙線性恆等式
`xᵀ[Sᵀ(G⊗G)S]y = (Sx)ᵀ(G⊗G)(Sy)`，而 `(G⊗G)vec(W) = vec(G·W·Gᵀ)`，
參照側只要兩次 n×n 乘法）後降到 1.94 秒，兩側對照仍 45/45 抓到。
詳見設計文件 §二十二。
