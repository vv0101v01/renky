## 一、第二次審視：第三輪做完之後，還剩什麼

第三輪解決的是「**接線**」問題 —— 把已有的零件接起來。
第二次審視針對的是零件**本身的能力上限**，這些問題第三輪一條都不會碰到。

### 1.1 ⚠️ 最嚴重的一條：引擎**挑選**規則，不**合成**規則

N-13 的報告裡，`adj/⊗/⊗ₛ` 被寫成「機器獨立尋獲」。看一下 `⊗ₛ` 的實作：

```
("⊗ₛ", (x, y, a, b, c) => {
  let n = a.mrows
  let m = b.mrows
  let s = cq_mul(c, qpow_cost(c, qdet_gauss(a,c), m-1),
                    qpow_cost(c, qdet_gauss(b,c), n-1))   // ← 手寫死的
  Some(qsmul_cost(c, s, qkron_cost(c, x, y)))
})
```

修正因子 `(det A)^{m−1}(det B)^{n−1}` **是我手打進去的**。
引擎做的只是從 6 條手寫規則裡挑中它。

> **這是整個 N 群最該被誠實面對的一點**：現行引擎的搜尋空間是
> `Φ × C × ⊙`，而 `⊙` 是一個**固定的、人寫的清單**（⊗、⊕、⊗ₛ、·、+、^）。
> 它永遠只能找到「人已經想得出規則形式」的律。
> 一個真正能發現未知演算法的系統，必須能**導出**修正因子，而不是被交付。

### 1.2 律全是一元或二元

```
fn check_law(   fn check_law1(      ← 全部
```

沒有任何三元以上的律。但 `A⊗B⊗C` 的結合方式、以及
k 因子 Kronecker 樹的**最佳結合順序**（類似矩陣鏈乘法的動態規劃問題），
是比二元律豐富得多的結構 —— 而 N-25 的模積法其實已經在用 k 元結構了，
只是沒有被當成「律」來搜尋。

### 1.3 沒有律的複合

每條律都是孤立的 `Φ(C(A,B)) = Φ(A) ⊙ Φ(B)`。
但 `Φ₂ ∘ Φ₁` 呢？例如：

```
inv(adj(A⊗B))      sqrtm(inv(A⊗B))      adj(adj(A⊗B))
```

若 Φ₁ 與 Φ₂ 各有律，複合是否自動有律？何時成立、何時失效？
這是一個**完全未探索**的空間，而它的大小是 Φ 集的平方。

### 1.4 N 群與 K/L/M 加速層零交互

```
nlaw.mbt 引用 CRT 層函式：1 次     rcost.mbt：0 次
```

本庫有兩套獨立的加速哲學：
- **K/L/M**：多模 𝔽p → CRT 提升 → 有理重建（代數的）
- **N**：結構律分解（幾何的）

兩者從未相乘。但 `det(A⊗B)` 在 𝔽p 上做、再 CRT 提升，
與先分解再模運算，成本完全不同 —— 這是個 10 × 21 的未探索乘積空間。

### 1.5 定律表沒有被持久化

```
無任何 cmd 執行檔輸出定律表
```

搜尋結果只活在義務的字串裡。沒有 `docs/定律表.tsv`，
下游（包括第三輪的 `PhiSpec` 自動產出）無從消費。
第三輪的 N-35 會順手做掉，但**沒有版本比對機制** ——
無法回答「這次搜尋比上次多找到／少找到哪幾條」。

### 1.6 義務全是手寫

189 條目錄，189 段手寫的 `ob_*` 函式與 `catalogue.mbt` 列。
即使第三輪讓引擎能自動合成演算法，**把一條新律變成一條目錄條目
仍然要人寫 60 行**。這是生成器與交付物之間最後一道人工關卡。

## 二、第四輪提案：從「挑選」到「導出」

第三輪的主題是接線，**第四輪的主題是讓引擎能產生它沒被教過的東西**。

### ✅ N-40 規則合成（ansatz 求解）—— **已交付**

不再從清單挑 `⊙`，而是設一個**帶未知數的規則型式**並解出未知數：

```
假設（矩陣值 Φ）：  Φ(A⊗B) = det(A)^α · det(B)^β · (Φ(A) ⊗ Φ(B))
假設（純量值 Φ）：  Φ(A⊗B) = Φ(A)^p · Φ(B)^q · n^r · m^s
```

**求解法**（精確、非擬合）：
取數個不同尺寸的對角／三角測試矩陣，兩側取對數後得到一個
**整數線性方程組**，以精確 ℚ 解之；解出 (α, β) 後再用隨機稠密矩陣驗證。

**預期自動導出**：
| Φ | 應解出 | 現況 |
| --- | --- | --- |
| `adj` | α = m−1, β = n−1 | 手寫 |
| `det` | p = m, q = n | 手寫 |
| `inv` | α = β = 0 | 手寫 |
| `Λᵏ det`（Sylvester–Franke） | 指數 C(n−1,k−1) | 手寫 |

**驗收**：把 `⊗ₛ` 從規則清單**刪除**，引擎必須仍能解出 adj 的律。
再以 Sylvester–Franke 作為留一驗證：不告訴引擎指數是 C(n−1,k−1)，
看它能否解出來。

> **交付結果**：驗收達成 —— adj 的 `p = m−1`、`q = n−1` 由精確 ℚ 的 3×3
> 方程組解出，原始碼中不存在任何 `m−1` 字樣。**覆蓋範圍**：一族待定式以
> `p`、`q` 為自由度，同時涵蓋 adj 的 Sylvester 型與 inv／sq／cube／transpose
> 的樸素型；待定式族本身亦為註冊表之一員，再登錄一族即令候選數相乘。

**風險**：中高。**預估**：300 行。

### ✅ N-41 k 元律與最佳結合順序 —— **已交付**

把律由二元推廣到 k 元：`Φ(A₁⊗…⊗A_k)`，並處理**結合順序**問題。

N-25 的模積法成本為 `Σᵢ N·nᵢ`，與因子順序無關；
但若 Φ 本身有不同成本（例如混合 eig 與 chol），順序就有差，
成為一個矩陣鏈乘法式的動態規劃問題。

**內容**：
- `check_law_k(Φ, C, ⊙, factors)` —— k 元裁決器
- 以 DP 求最佳結合樹，與貪心／左結合／右結合對照
- 驗收：k = 2 時退化為現行 `check_law`，結果逐例相同

> **交付結果**：退化性驗收達成（72 候選 × 4 樣本，相異 **0** 例，比的是
> 輸出而不只是裁決）。DP 的三個敗例都真的出現：(2,2,2,2) 左右皆輸、
> (5,2,2,5) 貪婪輸、(3,2,2,2,3) 平衡輸。**但本條最重要的是一個負面
> 結果**：組裝項對矩陣值 Φ 不會被分解消掉，增益上界由 Θ(N³/Σnᵢ³)
> 降為 Θ(N) —— N-03 的漸近宣稱高估了一個數量級。

**價值**：N-11 的 catamorphism 一直假設二元樹，k 元是它的自然上界。
**風險**：中。

### ✅ N-42 律之複合代數 —— **已交付**

研究 `Φ₂ ∘ Φ₁` 何時仍有律。

```
命題（待驗）：若 Φ₁(C(A,B)) = Φ₁(A) ⊙₁ Φ₁(B)
              且 Φ₂(X ⊙₁ Y) = Φ₂(X) ⊙₂ Φ₂(Y)
              則 Φ₂∘Φ₁ 有律，規則為 ⊙₂。
```

即：**律可複合的條件是中間規則 ⊙₁ 恰為 Φ₂ 的組合子。**
這給出一個可判定的充分條件，引擎可據以**免搜尋地推導**新律 ——
從 n 條律推出至多 n² 條，不必重新驗證。

**驗收**：以 `inv∘adj`、`det∘sq`、`sqrtm∘inv` 三例驗證推導正確，
並刻意找一個**不可複合**的例子（中間規則不匹配）說明條件之必要性。

> **交付結果**：驗收加強為**全量混淆表** —— 360 個複合候選全部實測，
> 導出且成立 60／導出但推翻 **0**／未導出但成立 4／未導出且推翻 296。
> 不可複合的例子正是 `adj` 作為內層：其規則 ⊗ₛ 不是組合子，定理接不上；
> 實測 `det∘adj/⊗/{·,+,^}` 三條全數推翻，確認引擎在此的沉默是對的。
> 第三格的 4 條說明條件**充分而不必要**，其中兩條經查是 ⊥ 造成的假象。
> `sqrtm∘inv` 屬 ℝ 軌，本輪複合器只做 ℚ 軌，未納入。

**價值**：這是第一條**關於律本身**的律（元層級），
能讓定律表自我擴張。**風險**：中。

### ✅ N-43 結構律 × CRT 加速層之乘積 —— **已交付（2026-10-07）**

把 N 群與 K/L/M 相乘。四條路徑對照：

```
(a) 直接精確 ℚ            (b) 先分解、再精確 ℚ（現行 N 群）
(c) 直接多模 CRT（現行 K/L/M）   (d) 先分解、每塊多模 CRT
```

**當初的預期**：(d) 最快，且增益約為 (b) 與 (c) 的乘積 —— 但這需要實測，
因為 N-12 的 Hadamard 敗績與 N-10 的線性冪陷阱都顯示
「兩個加速相乘」的直覺常常錯。

> ### ❌ 這個預期錯了，而且是錯在主要情形
>
> **⊗ 族 5/5 例，最快的是 (b) 而非 (d)。** 只有 Λᵏ 族 2/2 例是 (d) 最快。
>
> 增益也不可乘：交互作用 δ = (cb·cc)/(ca·cd) 在 inv 3⊗3 低到 **0.47**。
>
> **機制**（§12.3 of 設計構想）：同維度 12、同元素位寬下，A⊗B 的精確 ℚ
> 消去只需 9,627 字乘法、中間係數 204 位元，CRT 增益 **×1.03**；
> 一般稠密矩陣需 331,652 字乘法、506 位元，CRT 增益 **×31.46**。
> Kronecker 積根本不是會膨脹的矩陣 —— 而消除膨脹是 CRT 唯一的商品。
> **結構律與 CRT 搶的是同一塊餅。**
>
> 由此得到比「維度」更準的預測變數：**CRT 的獲益是係數膨脹幅度的函數，
> 不是維度的函數**；維度只是代理變數，在結構化矩陣族上完全失效。
>
> **交付物**：`ncrt.mbt`（四路徑量測 + 決策器 `pick_path`）、
> `oblig_ncrt.mbt`（定理 191-1…191-6）、目錄條目 N-43、設計構想 §十二。
> 決策器只看「分解後子問題維度 d」：d < 5 取 (b)，d ≥ 5 取 (d)，7/7 正確；
> 閾值 5 由獨立的維度掃描定出，非自這 7 例擬合。
>
> **對後續的影響**：N-40 的規則合成器若把各層增益當成可乘的，在這裡就會
> 給出錯誤建議。成本模型必須帶上「此路徑把問題推到哪個 régime」這一維。

## 四、兩輪合起來看

| | 主題 | 一句話 |
| --- | --- | --- |
| **第三輪** | **接線** | 把已有的零件接起來：搜尋引擎的輸出直接變成合成器的輸入 |
| **第四輪** | **導出** | 讓引擎產生它沒被教過的東西：從挑選規則到合成規則 |

**第四輪結束時應能說**：
> 給定一組構造子與一組演算法，引擎自行設定規則型式、解出修正因子、
> 驗證、複合既有律以推導新律、把結果寫成定律表、
> 並產出可執行的義務骨架。人只需補上代數證明。

第二輪結束時的機制是：
> 引擎枚舉 6 條已登錄的規則並逐一裁決，規則形式取自註冊表。

**第三、四輪把「規則形式」這一層也納入機制**：N-40 以待定式與
解係數取代逐條登錄，一族待定式即涵蓋該族全部係數。
